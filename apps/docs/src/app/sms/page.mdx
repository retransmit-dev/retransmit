# SMS

Send transactional SMS through the same Retransmit API key and SDK you use for
email. Retransmit detects the destination country and routes the message to an
available provider.

## Send a message

```ts
import { Retransmit } from "retransmit.dev";

const retransmit = new Retransmit(process.env.RETRANSMIT_API_KEY);

const { data, error } = await retransmit.sms.send({
  from: "Acme",
  to: "+237670000000",
  text: "Your order is ready for pickup.",
});
```

The `from` sender ID is optional. When provided, it can contain up to 11
letters, digits, spaces, hyphens, or underscores. If omitted, Retransmit uses
the routed provider's configured sender.

Recipients must be in international E.164 format, such as `+237670000000`.
You can send to one recipient or up to 50 recipients in one request, but all
recipients in that request must be in the same country.

## Routing and availability

Retransmit determines the destination country from the recipient number and
selects an available provider for that country. If no provider is configured
for the destination, the request returns `422 no_route` and is not queued.

For mixed-country recipient lists, send one request per country.

## Message segments

SMS billing is based on message segments, not API requests. The send response
includes `segments`, the number of billable GSM-7 or UCS-2 parts used by the
message. Unicode characters can reduce the number of characters that fit in
each segment.

```json
{
  "id": "sms_xxxxxxxxxxxx",
  "status": "queued",
  "country": "CM",
  "segments": 1,
  "created_at": "2026-09-01T12:00:00.000Z"
}
```

## Track delivery

Poll `retransmit.sms.get(id)` or [`GET /v1/sms/:id`](/sms/get)
to retrieve the current status and event history. For push updates, subscribe
to `sms.sent`, `sms.delivered`, `sms.undelivered`, and `sms.failed`
[webhooks](/webhooks).

See [Send SMS](/sms/send) for the complete request contract.
