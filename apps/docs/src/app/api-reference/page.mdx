# API Reference

## SDKs

| Language | Package | Install |
| --- | --- | --- |
| Node.js / TypeScript | [`retransmit.dev`](https://www.npmjs.com/package/retransmit.dev) | `npm install retransmit.dev` |

The SDK wraps every endpoint below with typed methods (`emails.send`,
`emails.get`, `batch.send`, `batch.get`, `sms.send`, `sms.get`,
`whatsapp.send`, and `whatsapp.get`) and returns
`{ data, error }` instead of throwing on API errors. Each endpoint page shows
the SDK call alongside the raw HTTP request. Other languages can call the HTTP
API directly.

## Base URL

| Environment | Base URL |
| --- | --- |
| Production | `https://api.retransmit.dev` |
| Local development | `http://localhost:3002` |

All endpoints are versioned under `/v1`.

## Authentication

Every request must include your API key as a Bearer token:

```sh
Authorization: Bearer rt_xxxxxxxxxxxxxxxx
```

Keys are created in the dashboard and shown once. A missing, malformed, or
revoked key returns `401 unauthorized`:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Provide your API key as `Authorization: Bearer rt_...`"
  }
}
```

## Response format

Responses are JSON. Errors always have the shape:

```json
{
  "error": {
    "code": "some_error_code",
    "message": "Human-readable explanation"
  }
}
```

See [Errors](/api-reference/errors) for the full list of codes.

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `POST` | [`/v1/emails`](/email/send) | Queue a transactional email |
| `POST` | [`/v1/emails/batch`](/email/send-batch) | Queue up to 10,000 emails in one request |
| `GET` | [`/v1/emails/:id`](/email/get) | Retrieve an email and its event history |
| `GET` | [`/v1/emails/batch/:id`](/email/get-batch) | Batch progress: counts per status |
| `POST` | [`/v1/sms`](/sms/send) | Queue an SMS |
| `GET` | [`/v1/sms/:id`](/sms/get) | Retrieve an SMS and its event history |
| `POST` | [`/v1/whatsapp`](/whatsapp/send) | Queue a WhatsApp message |
| `GET` | [`/v1/whatsapp/:id`](/whatsapp/get) | Retrieve a WhatsApp message and its event history |
| `GET` | `/health` | Health check (no auth required) |

## Asynchronous sending

Submitting an email, SMS, or WhatsApp message returns `202 Accepted` immediately with status
`queued`. A worker drains the queue at the provider's rate, retries transient
failures with exponential backoff, and marks a message as `failed` only after
all retries are exhausted. Track outcomes by polling the matching email, batch,
SMS, or WhatsApp endpoint, or receive push updates through [Webhooks](/webhooks).
