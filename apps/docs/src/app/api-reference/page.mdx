# API Reference

## Base URL

| Environment | Base URL |
| --- | --- |
| Production | `https://api.retransmit.dev` |
| Local development | `http://localhost:3002` |

All endpoints are versioned under `/v1`.

## Authentication

Every request must include your API key as a Bearer token:

```sh
Authorization: Bearer rt_xxxxxxxxxxxxxxxx
```

Keys are created in the dashboard and shown once. A missing, malformed, or
revoked key returns `401 unauthorized`:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Provide your API key as `Authorization: Bearer rt_...`"
  }
}
```

## Response format

Responses are JSON. Errors always have the shape:

```json
{
  "error": {
    "code": "some_error_code",
    "message": "Human-readable explanation"
  }
}
```

See [Errors](/api-reference/errors) for the full list of codes.

## Endpoints

| Method | Path | Description |
| --- | --- | --- |
| `POST` | [`/v1/emails`](/api-reference/send-email) | Queue a transactional email |
| `POST` | [`/v1/emails/batch`](/api-reference/send-batch) | Queue up to 10,000 emails in one request |
| `GET` | [`/v1/emails/:id`](/api-reference/get-email) | Retrieve an email and its event history |
| `GET` | [`/v1/emails/batch/:id`](/api-reference/get-batch) | Batch progress: counts per status |
| `GET` | `/health` | Health check (no auth required) |

## Asynchronous sending

Submitting an email returns `202 Accepted` immediately with status `queued`.
A worker drains the queue at the platform's provider rate, retries transient
failures with exponential backoff, and dead-letters an email as `failed` only
after all retries are exhausted. Track outcomes by polling
[Get Email](/api-reference/get-email) / [Get Batch](/api-reference/get-batch),
or push-based via [Webhooks](/webhooks).
